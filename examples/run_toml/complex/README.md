# Complex scenario — sloping floodplain with inflow and rain

A "Cairns-like" `anuga_toml_run` scenario, scaled down so it runs anywhere in a
minute or two with no external datasets. A 400 m × 200 m plain slopes from 3 m
elevation in the west down to 0 m at an eastern outlet. Water enters from an
inlet hydrograph in the west, rain falls over the whole domain, and everything
drains out through a prescribed-stage boundary on the east.

It exercises most of the features the full Cairns example uses, but every input
is a small CSV generated by `make_inputs.py`:

- elevation from an `x,y,z` point file (a sloped bed),
- an interior region meshed at a finer resolution,
- an inlet hydrograph (discharge injected across a line),
- spatially uniform rainfall (a timeseries over the whole domain),
- a prescribed-stage (transmissive, GPU-friendly) outlet boundary with
  reflective walls elsewhere,
- evolve-loop diagnostics via a `user_functions.py` module.

## Files

| File | Role |
|------|------|
| `floodplain.toml` | the scenario definition (heavily commented) |
| `make_inputs.py` | regenerates the CSVs below; run it to experiment with the geometry |
| `bounding_polygon.csv` | `x,y` domain outline (no header) |
| `elevation.csv` | `x,y,z` sloped bed (header row `x,y,z`) |
| `refine_channel.csv` | `x,y` interior-region polygon, meshed finer (no header) |
| `inlet_line.csv` | `x,y` cross-section line the inlet injects across (no header) |
| `inlet_hydrograph.csv` | `time,discharge` inflow timeseries (header row) |
| `rain.csv` | `time,rain_mm_hr` rainfall timeseries (header row) |
| `downstream_stage.csv` | `time,stage` for the eastern outlet boundary (header row) |
| `user_functions.py` | optional evolve-loop reporting hooks |

The CSVs are committed, so you can run immediately. To regenerate them (e.g.
after changing the geometry in `make_inputs.py`):

```bash
python make_inputs.py
```

## Run it

```bash
# serial
anuga_toml_run floodplain.toml

# parallel (e.g. 4 processes)
mpiexec -np 4 anuga_toml_run floodplain.toml
```

In a source checkout without the installed command, use
`python <repo>/scripts/anuga_toml_run.py floodplain.toml`.

## What you get

A new `OUTPUT/RUN_<timestamp>_floodplain/` directory with `floodplain.sww`, the
`Simulation_logfile.log`, a `code/` copy of the inputs, and peak-quantity
rasters. With the reporting flags on (see below) each yieldstep prints mass
conservation, the peak flow speed per rank, and the current rate of each
rainfall/inlet operator.

> A final `GeoTif creation failed: ...` message is harmless — it is a known
> issue in the optional GeoTIFF export step and does not affect the `.sww`
> output.

## Reporting hooks (`user_functions.py`)

`anuga_toml_run` imports a `user_functions` module from the scenario directory
when present and calls these hooks each yieldstep, gated by `[project]` flags in
the TOML:

| TOML flag | Hook called |
|-----------|-------------|
| `report_peak_velocity_statistics` | `print_velocity_statistics(domain, max_quantities)` |
| `report_operator_statistics` | `print_operator_inputs(domain)` |

Set those flags to `false`, or delete `user_functions.py`, to run without the
extra output.

## Things to try

- Steepen or flatten the bed, or move the inlet, by editing `make_inputs.py` and
  rerunning it.
- Raise the storm: increase the rates in `rain.csv` or the peak in
  `inlet_hydrograph.csv`.
- Raise the sea: increase the stage in `downstream_stage.csv` to push water back
  up the plain.
- Add a structure: a `[[culverts]]`, `[[weirs]]`, `[[bridges]]`, or
  `[[pumping_stations]]` block — see
  [`../cairns/cairns_example.toml`](../cairns/cairns_example.toml)
  for fully documented examples of each.

See [`../README.md`](../README.md) for the file-format reference and
[`../cairns/`](../cairns/) for the full real-world Cairns dataset.
